## 通用核算链

- 绩效总分：各 KPI 的“最终得分”按源表公式加总；标准岗位表公式为 `权重 × 完成结果`，客服表为 `权重 × 完成结果`。
- 达成率型指标：源表有明确公式时按原文（通常为实际值 ÷ 目标值）计算，再按各指标评分标准给分；不得将不同岗位的阈值互相套用。
- 定性、次数、扣分、奖惩类指标：输入须保留数据来源与评价周期；源表未提供统一换算公式的，不得由 ETL 推断最终分数。
- 评价周期：除源表另有范围说明外，均为每月5日完成核算、取上月整月。制作部同时限定“上传时间90天内素材的上月整月消耗”。

## 财务/业务口径（仅源文件明确内容）

- GSV：源表表述为“退货后营收（GSV）”，用于多个团队营收达成指标；实际值与预算目标的口径仍须保持同一渠道/范围。
- ROI：兴趣电商相关岗位使用“签收ROI”，按实际签收ROI ÷ 预算目标签收ROI计算（仅在明确填写公式的岗位中适用）。
- 制作部消耗：数据源为云视频管家，且计算范围为上传时间90天内素材的上月整月消耗。编导「团队产出消耗金额」**打分**口径例外（D-016 已定）：分子=项目组总消耗（总消耗口径，无 90 天区分，与 V60 预算总消耗分母对齐）；「近90天成片」约束仅保留在编导**提成**口径（个人近90天成片消耗 × 档位比例），见「制作部核算规则」章。

### 0. 术语与公式

| 术语 | 定义 |
|---|---|
| Commission_Base（提成金额基数） | 提成的**金额基数**，按岗位族区分（D-009 口径）：渠道 GSV / 个人消耗 / 个人营收达成等，取值自 Actual 表 |
| Commission_Ratio（提成比例） | 按月度总分命中梯度档位后取用的**比例系数**：运营/高级主管=固定提成基数（Base_Rate 配置，当前 0.003）× 档位系数；其余岗位=档位纯数值比例 |
| Commission_Amount（提成金额） | 提成金额 = 提成金额基数 × 提成比例 |

- 计算公式：`Commission_Amount = Commission_Base × Commission_Ratio`
- 计算链衔接：月度总分（Monthly_Total）→ 梯度档位（Commission_Tier_Level，T9b 已落地，D-009.5 超上限按最高档）→ 提成比例（Commission_Ratio）→ 提成金额（Commission_Amount，T11c 落地）
- **术语注意（同名异义）**：源表「提成比例基数」= 0.003（**比例基数**，V05 新规则 sheet F32:F45；V04 原锚点 K12/M12 已随内嵌表移除）；D-009「提成基数口径」= **金额基数**（渠道 GSV / 个人消耗 / 个人营收）。两者不是同一对象，本章分别以 Commission_Ratio 固定基数（Base_Rate 配置，当前 0.003）与 Commission_Base（金额）区分，使用时不得混用。
- **配置化（D-010-R2，已定）**：0.003 只是运营岗**当前**比例基数，不是规则常量。正式实现必须从 `Commission_Tier.Base_Rate` 读取（按岗位族绑定，改配置即生效，不碰公式）；豁免适用范围从 `Exemption_Scope` 表读取（岗位/岗位族 × 渠道 × 阈值，新增范围=新增行，禁止写死单一岗位）。详见 `docs/D010-R2_豁免提成基数可配置化规格.md`。

### 3. 提成金额计算

- 通用公式：`Commission_Amount = Commission_Base × Commission_Ratio`
- Commission_Ratio 按岗位族取值：

| 岗位族 | Commission_Ratio 取值 | 说明 |
|---|---|---|
| 运营（运营/高级主管） | `Commission_Tier.Base_Rate × Commission_Tier.Coefficient`（Base_Rate 配置=当前 0.003 × 档位系数） | V05 新表公式 =F{行}*G{行}（基数 0.003×系数，F32:F45）；D-010-R2 起读配置表，不硬编码 |
| 主播 | `Commission_Tier.Ratio_Value`（0.001/0.002/0.004/0.005） | M 列直接数值 |
| 内容部（编导/视频剪辑/摄影师） | `Commission_Tier.Ratio_Value`（0/0.001/0.003/0.0045；摄影师第3档0.0015/第4档0.002） | M 列直接数值；准入须满足 D-006 抖音/视频号范围 |
| 其他-广告投放 | `Commission_Tier.Ratio_Value`（0.001 平档） | M 列直接数值；提成口径 D-017 已定=投放账户广告消耗（4 档 0.001，GSV 口径待 HR 复核）；消耗达成值=当月导入即最终（D-015，见「广告投放消耗口径」章） |
| 其他-直播中控 | 不适用基数×比例；收入 = 绩效工资×档位百分比（80%/90%/100%/110%）＋ 渠道GSV×0.001÷中控人数（D-013） | 见「直播中控收入规则」章 |
| 其他-客服 | 不适用公式；客服主管手动录入 | 见 §2.7 |

- 档次命中：月度总分（Monthly_Total）→ `Commission_Tier_Level`（T9b 公式：取 Score_Lower ≤ 总分 的最高档，Status=Active）→ 按该档取 Commission_Ratio。
- 示例（运营，渠道 GSV 实际达成 100 万，月度总分 95 → 第4档 90≤95<100）：Commission_Ratio=Base_Rate(0.003)×0.6=0.0018，Commission_Amount=1,000,000×0.0018=1,800 元。

### 4. 边界规则

1. **超梯度上限（D-009.5，已定）**：得分超出有上限梯度的最高分档时，按最高一档处理，不外推。该兜底与 `Upper_Is_Open`「不封顶」语义不同：前者针对有上限梯度被超出，后者针对 V04 原文即不设上限（如运营/高级主管第7档 108+）。两者不得混用（模型 §5.5）。
2. **无梯度匹配（V04 未规定【待PO确认】）**：正常情形各岗位最低档下限=0，有总分即可匹配；运营/高级主管/制作部最低档比例=0（0-50/0-60 分），命中即提成为 0。直播中控的 [0,60) 档边界已按 V04 同步，该档绩效工资部分比例=80%（D-013）；客服无梯度，不适用。
3. **新项目豁免（D-010-R3，PO 已确认；权威载体 D-032 已切换）**：新项目机制/免责提成/达成激励的权威源为 V05「绩效豁免规则」sheet（4 项目行 + 2 星注：高个子-抖音按绩效考核得分取提成系数×固定基数；高个子-视频号/少年状元/骨能按新项目机制考核，享受免责提成+达成激励；脱离条件=暂定单月GSV达成100万或运营两个月，满足任意条件。星注：免责提成=新项目免责期内按提成基数×0.8 作为项目免责提成比例；新项目达成激励=免责期内达成预算目标取项目利润 3% 作为项目激励）。适用范围与两个阈值均由 `Exemption_Scope` 配置表承载（当前种子=抖音兴趣电商运营岗，EXS000001；运行天数上限=90天、当月营收上限=1,000,000元）。豁免成立 = 命中配置范围 **且** 项目运行天数 `< Max_Project_Run_Days` **且** 同项目/渠道/期间的 Actual 退货后 GSV `≤ Max_Monthly_Revenue`；运行超过90天自动脱离，90天窗口内任一月营收超过100万元即该月脱离。营收 Actual 由 `Performance_Result.Revenue_Actual_ID` 溯源，缺失时 Is_Exempt 留空并标记「营收未知【待确认】」，不按0或任意默认值判定。评分及加权照常；豁免期提成为配置基数（`Commission_Tier.Base_Rate`，当前0.003）× 达成GSV，直接跳过梯度/系数。**0.003不是常量**：由 Base_Rate 配置按岗位族绑定，改配置即生效、不碰公式；豁免适用范围扩展=新增 Exemption_Scope 行。高级主管旧的 HR 人工评判规则仍按其独立口径处理，不得混同。
4. **消耗分奖金范围（D-006 + D-017，已定）**：广告投流费=消耗；仅抖音/视频号两个平台的内容制作团队从消耗中分奖金，其他平台/岗位不适用。制作部梯度 `Applicable_Scope` 已承载；广告投放以「投放账户广告消耗」为提成来源但岗位非内容制作团队，D-017（2026-08-17 PO）已确认按 V04 原文口径推进提成（4 档 0.001），其 `Applicable_Scope` 注记「不适用D-006消耗分奖金范围」成立；GSV 口径待 HR 复核（见 §5 第 6 条）。
5. **多人共用提成基数（D-013/D-014 已定）**：运营岗渠道 GSV、直播中控渠道 GSV 为渠道级金额。分摊口径已由 PO 拍板——运营/高级主管按**各自负责的渠道全额计提**（不按比例分摊，D-014）；直播中控按**对应渠道下所有中控总人数均分**（渠道GSV×0.001÷中控人数，D-013）。其余岗位（主播/内容部）基数为个人级，无此问题。中控人数取值口径见「直播中控收入规则」章（负责该渠道的中控在岗人数）。

### 6. 绩效工资核算公式（V05 新增计算链，D-032 C-3）

> 来源：V05「提成比例与绩效工资核算规则」sheet「对应绩效工资核算公式」列（V04 全文无此公式，属新增全局规则）。D-032（2026-08-21 PO）裁决接入该计算链；**合同化（C0 增补）另发卡，本节为文档级规则，T11c 及引擎不得在合同化前实现**。

#### 6.1 公式与业务含义

```
应发绩效工资 = 绩效得分 ÷ 100 × 绩效工资基数
```

- **业务含义**：绩效得分 100 分为足额基准——得分 100 拿满绩效工资基数；低于 100 按比例折减（如 80 分拿 80%），高于 100 按比例上浮（如 110 分拿 110%）。该公式把「绩效得分」与「绩效工资」线性挂钩，是 V05 新增的得分→薪酬换算链。
- **绩效工资基数**：花名册维护，字段=`Employee.Perf_Salary`（data_model.md §4.1；计算时快照入 `Performance_Result.Perf_Salary_Snapshot`，§5.4）。
- **绩效得分**：即月度总分（Monthly_Total），与提成梯度档位命中共用同一得分，不另行计算。

#### 6.2 例外：直播中控按档位系数（不走线性折算）

中控绩效工资不按「得分/100」线性折算，而按月度总分命中梯度档位取档位系数（V05 新表第 24-27 行 I 列）：

| 档位 | 得分区间（含下限，不含上限） | 绩效工资档位系数 |
|---|---|---|
| 1 | [0, 60) | 0.8 |
| 2 | [60, 80) | 0.9 |
| 3 | [80, 100) | 1.0 |
| 4 | [100, 150) | 1.1 |

即：中控应发绩效工资 = 绩效工资基数 × 档位系数（与 D-013「绩效工资×档位百分比 80%/90%/100%/110%」**数值等值**，见「直播中控收入规则」章）。

#### 6.3 边界与异常（含待确认标注）

1. **得分 >100 / <0 的截断【待业务确认】**：源表未规定是否截断。D-032 裁决：实现时按**不截断+留痕**处理（得分 110 → 按 1.1 倍计发并留痕；得分 <0 → 按实际折算并留痕），待业务补充口径后再定是否加封顶/封底。已登记 §5 待确认清单第 7 条。
2. **得分超 150（有上限梯度岗位）**：提成侧按 D-009.5 超上限兜底=最高档；绩效工资线性折算侧无梯度概念，按 6.1 公式照算（如 160 分 → 1.6 倍）——该场景源表未说明，与第 1 条一并待业务确认。
3. **人员中途调整**：绩效工资基数以核算期间的花名册快照为准（`Perf_Salary_Snapshot`），期间内调薪/调岗按生效区间切分（同 D-008 员工主数据维护口径）；月中入离职按在职工况折算规则另待 HR 口径（本章不自行规定）。
4. **多人参与项目**：本公式为个人绩效工资折算，按个人月度总分逐人计算，不存在多人分摊；涉及团队口径的得分来源（如编导团队指标、中控渠道 GSV）已在各 KPI/提成规则节定义，不影响本公式的个人粒度。
5. **与提成计算的关系**：绩效工资折算（本节）与提成计算（§3）是两条独立链，共用同一月度总分，互不作为对方输入；客服无自动公式（人工录入，§2.7），不适用本节。

## 直播中控收入规则（D-013，T17 落文）

> 起草：Business Analyst（T17，2026-08-18）。依据决策日志 D-013（PO 拍板，2026-08-17）+ D-013 澄清（百分比按得分档位对应，与提成梯度同款逻辑，非得分×百分比）。BA 起草，Finance Controller 与 Product Owner 已确认（三方确认制，2026-08-18）。

### 1. 收入构成

直播中控/运营助理（POS000041）的绩效考核收入 = **绩效工资部分** + **提成收入部分**：

```
绩效考核收入 = 绩效工资 × 档位百分比（80%/90%/100%/110%）＋ 渠道GSV × 0.001 ÷ 中控人数
```

### 2. 绩效工资部分（花名册字段依赖）

- 绩效工资基数：花名册维护，字段=`Employee.Perf_Salary`（data_model.md §4.1，CHG-T18-001 已落地；计算时快照入 `Performance_Result.Perf_Salary_Snapshot`，§5.4）。
- 档位百分比按月度总分命中梯度档位（与提成梯度同款逻辑，非得分×百分比）：

| 档位 | 得分区间（含下限，不含上限） | 绩效工资档位百分比 |
|---|---|---|
| 1 | [0, 60) | 80% |
| 2 | [60, 80) | 90% |
| 3 | [80, 100) | 100% |
| 4 | [100, 150) | 110% |

### 3. 提成收入部分

- 基数：所负责渠道的 GSV（`Actual_Value`，渠道级，与运营同源）。
- 比例：0.001（V04 原文为「0.1%/中控人数」；0.1%=0.001，**数值等价**，PO 口径以 0.001 表述——差异仅表述形式，记录于文末）。
- 分摊：**对应渠道下所有中控总人数均分**（每人 = 渠道GSV×0.001÷中控人数）。
- 中控人数取值口径：花名册中负责该渠道、岗位为直播中控/运营助理的在岗人数（Employment_Status=在职）；以花名册「负责渠道」字段为准（`Employee.Responsible_Channel_IDs`，data_model.md §4.1，CHG-T18-001 已落地）。
- 中控负责渠道关系：花名册维护，字段=`Employee.Responsible_Channel_IDs`（多值 link→Channel，data_model.md §4.1，CHG-T18-001 已落地）。

### 4. 数字示例

例：某渠道当月 GSV=300 万，花名册中负责该渠道的在岗中控共 3 人；某中控月度总分=95（命中第 3 档 [80,100)，档位百分比=100%），其绩效工资=5,000 元。

```
绩效工资部分 = 5,000 × 100% = 5,000 元
提成收入部分 = 3,000,000 × 0.001 ÷ 3 = 1,000 元
绩效考核收入 = 5,000 + 1,000 = 6,000 元
```

### 5. 异常与边界

- 中控人数=0（该渠道无在岗中控）：提成收入部分不产生，仅记绩效工资部分；系统不得除零，须 Error_Log（PROJECT_RULES §15）。
- 人员中途调整：负责渠道变更以花名册生效区间为界，按期间归属（同 D-008 员工主数据维护口径）。
- 得分超 150：按 D-009.5 超梯度上限兜底=最高一档（110%），不外推。
- 档位与提成梯度共用同一月度总分（Monthly_Total），不另行计算。

## 渠道 GSV 分摊规则（D-014，T17 落文）

> 起草：Business Analyst（T17，2026-08-18）。依据决策日志 D-014（PO 拍板，2026-08-17）。BA 起草，Finance Controller 与 Product Owner 已确认（三方确认制，2026-08-18）。

### 1. 规则

运营（兴趣电商运营 POS000013）与高级主管（兴趣电商运营高级主管 POS000017）均按**各自负责的渠道全额计提**，不按比例分摊。

- 典型结构：一个运营负责一个渠道；一个高级主管负责多个渠道并管理多个运营。
- 同一渠道被多人负责时（如运营+其高级主管同渠道）：各按全额计提，**不因上级/下级同时负责而削减任一方**。
- 负责人之间的层级关系（运营 vs 高级主管）不影响计提金额，只影响适用岗位族梯度（§2.1/§2.2）。

### 2. 数据依赖

- 负责渠道关系：花名册/组织架构维护（员工-渠道负责关系；高级主管多渠道场景须支持一对多），字段=`Employee.Responsible_Channel_IDs`（多值 link→Channel，data_model.md §4.1，CHG-T18-001 已落地）。
- 计提金额 = 渠道 GSV × 该员工岗位族的 Commission_Ratio（详见「提成计算规则」章 §3，运营与高级主管第 4 档系数差 0.2）。

### 3. 数字示例

例：某高级主管负责抖音、视频号两渠道，另有一运营负责抖音渠道。当月抖音 GSV=200 万、视频号 GSV=80 万；两人月度总分均=95（运营命中第4档 0.6、高级主管命中第4档 0.8）。

```
高级主管计提基数 = 抖音 GSV 200万 + 视频号 GSV 80万 = 280万（各自负责渠道全额，相加）
运营计提基数   = 抖音 GSV 200万（其负责渠道全额，不与高级主管分摊）
高级主管提成 = 2,800,000 × (0.003 × 0.8) = 6,720 元
运营提成     = 2,000,000 × (0.003 × 0.6) = 3,600 元
```

### 4. 边界

- 无负责渠道关系（花名册缺失）：该员工不参与 GSV 提成计提，须 Error_Log 提示主数据缺失（禁止静默按空渠道=0 处理）。
- 新项目豁免（D-010-R1/R2）：按 Exemption_Scope 命中判断，与分摊规则正交，不冲突。

### 2. 核算公式（可执行版）

```
视频剪辑「个人成片消耗金额」得分：
  个人贡献率 = 个人消耗达成金额 ÷（当月项目总消耗 ÷ 项目组剪辑人数 × 0.9）
  评分：贡献率 ≤ 80% → 0分；80% ＜ 贡献率 ≤ 100% → 90分；贡献率 ≥ 100% → 按实际达成取两位小数，封顶系数 1.5

编导「团队产出消耗金额」得分（打分口径，D-016 已定）：
  达成率 = 当月项目组总消耗 ÷ 项目预算目标消耗值
  分子=项目组总消耗：总消耗口径，无 90 天区分（V60 预算为总消耗口径，分子与分母对齐；F8 原意「近90天成片消耗」作废）
  评分：达成率 ≤ 80% → 0分；80% ＜ 达成率 ≤ 100% → 90分；达成率 ≥ 100% → 按实际达成取两位小数，封顶系数 1.5

编导「团队产出消耗金额」提成（提成口径，D-016 已定，与打分分离）：
  Commission_Base = 个人近90天成片消耗（个人口径，奖励个人新增产出；历史素材不提成）
  Commission_Amount = 个人近90天成片消耗 × Commission_Tier.Ratio_Value（编导 4 档：0/0.001/0.003/0.0045）
  爆款激励不受影响：近90天单视频消耗超50万，1500元/片

摄影师「个人素材数量」得分（D-017 已定）：
  达成率 = 个人发布工单数 ÷ 工单任务数
  评分：达成率 < 100% → 0分；达成率 ≥ 100% → 100分
```

提成（各岗位按个人基数 × 档位比例，D-006 准入：仅抖音/视频号内容制作团队）：

```
Commission_Amount = Commission_Base × Commission_Tier.Ratio_Value
  Commission_Base：编导/视频剪辑=个人上传素材广告消耗（编导按 D-016 =个人近90天成片消耗，历史素材不提成）；摄影师=个人拍摄素材消耗
```

### 3. 数字示例

- 视频剪辑：当月项目总消耗=100 万、项目组剪辑人数=5 → 人均=20 万、门槛=20万×0.9=18 万。个人消耗达成=16 万 → 贡献率=16/18≈88.9% → 90 分；提成基数=16 万，总分 95 命中档3 → 160,000×0.003=480 元。
- 编导（打分，D-016 总消耗口径）：所带小组覆盖项目当月**项目组总消耗**=90 万（其中近90天成片消耗=60 万、历史素材消耗=30 万）、项目预算目标消耗=100 万 → 达成率=90/100=90% → 90 分。若按旧 F8 近90天成片口径则=60/100=60%，历史素材占比 33% 将拉低达成率——D-016 已作废该口径，避免历史素材占比例导致永远无法达成。
- 编导（提成，D-016 个人口径）：该编导个人近90天成片消耗=40 万、月度总分 95 命中档3（[80,100)）→ Commission_Amount=400,000×0.003=1,200 元；其个人历史素材消耗（如 10 万）**不计提成**。
- 摄影师（D-017 边界）：当月工单任务=10 个、个人发布工单=10 个 → 达成率=100% → 100 分；若个人发布工单=9 个 → 达成率=90% < 100% → **0 分**（非 100 分，消除重叠歧义）。提成基数=个人拍摄素材消耗，命中档位后按比例计提。
