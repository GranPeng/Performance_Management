# 计算链公式说明（T9b 交付物）

> 任务：T9b 计算链公式实现：Performance_Result 表 V04 评分公式落地
> 日期：2026-08-17
> 状态：V04 全链路公式已落地，模拟数据验证 90/93 自动评分与 T9a 预期一致，3 条差异为 T9a 模拟简化（见【已知限制】L1）
> 规则依据：docs/绩效框架结构化规则.md（V04 原文）、docs/data_model.md §5.4/§5.5（FROZEN）、context/decision_log.md（D-009.3/D-009.5/D-005/D-006）

## 1. 计算链总览

```
Target + Actual
   │  Actual_Value / Target_Value（Achievement_Rate 公式字段）
   ▼
达成率
   │  按 Scoring_Type 分档（Auto_Score 公式字段，5 类模板）
   ▼
单项自动得分（Auto_Score）
   │  Auto_Score + Manual_Score（Final_Score 公式字段，双部分 D-009.3）
   ▼
最终单项得分（Final_Score）
   │  Σ(Weight × Final_Score) 按员工+期间（Monthly_Total 公式字段）
   ▼
岗位月度总分（Monthly_Total）
   │  按总分对照 Commission_Tier 取档（Commission_Tier_Level 公式字段，D-009.5 兜底）
   ▼
提成梯度档位（Commission_Tier_Level）
```

计算链全部由 Performance_Result 表的**公式字段**承载，Agent 只写存储字段（Actual_ID/Target_ID/参数快照等），公式层自动产出解释链，符合 data_model §5.4「由飞书计算引擎产生；Agent 禁止直接修改」。

## 2. 公式字段清单（Performance_Result，tbl6tFtVKExFUTWo）

| 字段 | 类型 | 公式（expression） | 说明 |
|---|---|---|---|
| Achievement_Rate | formula | 见 §3.1 | 达成率 = Actual_Value / Target_Value |
| Weight | formula | `FIRST([Metric_ID].[Weight])` | 权重 lookup 自 Metric.Weight |
| Auto_Score | formula | 见 §3.2 | 按 Scoring_Type 分档，5 类模板 |
| Final_Score | formula | 见 §3.3 | Auto_Score + Manual_Score（双部分 D-009.3） |
| Weighted_Score | formula | `IFBLANK([Weight],0) * IFBLANK([Final_Score],0)` | 加权得分中间量 |
| Monthly_Total | formula | 见 §3.4 | 岗位月度总分（同员工+期间 Σ Weighted_Score） |
| Commission_Tier_Level | formula | 见 §3.5 | 提成梯度匹配（D-009.5 超上限按最高档） |

### 辅助参数列（Performance_Result 新增，评分参数快照）

分档参数不硬编码在公式内，而是作为**每行的评分参数快照**（与 Weight 快照同语义，防 Metric 改版后历史失真），由结果生成时从 V04 规则转写填充：

| 列 | 含义 | 用途 |
|---|---|---|
| Target_Value_Snapshot | 目标值快照 | 达成率计算：无 Target_ID 可关联（ROI 派生/评分标准基准值）时使用 |
| Rate_T1 / Score_T1 | 档1阈值/得分 | 达成率型：rate≥Rate_T1 时，Score_T1=0 表示按 rate×100 封顶计入；非 0 表示固定分（如 CAM-002 满分 100） |
| Rate_T2 / Score_T2 | 档2阈值/得分 | 达成率型第二档 |
| Rate_T3 / Score_T3 | 档3阈值/得分 | 达成率型第三档 |
| Score_Cap | 封顶值 | 达成率型最高档封顶（150/120/110 等） |
| Score_Floor | 保底值 | 各类型兜底得分（通常 0） |
| Deduct_Per | 单次扣分 | 扣分制每次扣分值（V04 原文 5 分） |

> 说明：这些列是**评分参数快照**（同 Weight 快照语义），由 T9b 结果生成时从 V04 评分标准原文转写；不是新增业务字段。Metric 表 Score_Cap_Value/Score_Floor_Value 目前为空（BA 结构化容器未填充），故参数以结果表快照承载，见【已知限制】L2。

## 3. 公式实现细节

### 3.1 Achievement_Rate（达成率）

```text
IF(ISBLANK(FIRST([Actual_ID].[Actual_Value])), "",
   IFERROR(FIRST([Actual_ID].[Actual_Value]) /
     IF(ISBLANK([Target_ID]), [Target_Value_Snapshot], FIRST([Target_ID].[Target_Value])), ""))
```

- 有 Target_ID 关联（GSV 类 → Target 表 V60 行3 主营业务收入；消耗类 → 行11 广告投流费）时，从 Target 表 lookup Target_Value
- 无 Target_ID 可关联时（ROI 派生目标、V04 评分标准基准值），用 Target_Value_Snapshot 快照
- 次数阈值型/扣分制/定性/奖惩：无达成率语义 → 返回空
- 除法出错（如除零）→ IFERROR 返回空

### 3.2 Auto_Score（自动得分，5 类模板）

```text
SWITCH(FIRST([Metric_ID].[Scoring_Type]),
  "达成率/进度型", IF(ISBLANK([Achievement_Rate]), "",
    IF([Achievement_Rate] >= [Rate_T1],
       IF([Score_T1] = 0, MIN([Achievement_Rate]*100, [Score_Cap]), [Score_T1]),
       IF([Achievement_Rate] >= [Rate_T2], [Score_T2],
          IF([Achievement_Rate] >= [Rate_T3], [Score_T3], [Score_Floor])))),
  "次数阈值型", IF(ISBLANK(FIRST([Actual_ID].[Actual_Value])), "",
    IF(FIRST([Actual_ID].[Actual_Value]) <= [Rate_T1], [Score_T1],
       IF(FIRST([Actual_ID].[Actual_Value]) < [Rate_T2], [Score_T2], [Score_Floor]))),
  "扣分制", IF(ISBLANK(FIRST([Actual_ID].[Actual_Value])), "",
    MAX(100 - FIRST([Actual_ID].[Actual_Value]) * [Deduct_Per], [Score_Floor])),
  BLANK())  /* 定性等级型/奖惩制 → Auto_Score 留空，走 Manual_Score */
```

各类型模板与 V04 原文对照：

| Scoring_Type | 模板逻辑 | V04 原文示例 | 封顶/保底 |
|---|---|---|---|
| 达成率/进度型 | 达标档按实际达成×100 封顶计入，其后按档位降分 | 「达成率≥100%：按实际达成取两位小数计入，最高150分；100%＞达成率≥80%，90分；80%＞达成率≥60%，60分；60%＞达成率，0分」 | 封顶=Score_Cap（150/120/110），保底=0 |
| 次数阈值型 | 次数≤档1阈值→档1分；次数<档2阈值→档2分；否则保底 | 「错误次数=0次，得100分；错误次数<3次，得80分；错误次数≥3次，得0分」 | 保底=0 |
| 扣分制 | MAX(100 − 次数×Deduct_Per, Score_Floor) | 「出现与目标相悖的情况，单次扣除5分」 | 基准100，每次扣5，保底0 |
| 定性等级型 | Auto_Score 留空（BLANK→空） | 「0-60分，差；60-80分，合格；80-100分，优秀」 | 人工录入 Manual_Score（D-009.3） |
| 奖惩制 | Auto_Score 留空（BLANK→空） | 客服奖励/处罚金额 | 人工录入 Manual_Score（D-009.3） |

**评分参数转写**（T9b 生成结果时填充辅助列，与 T9a 预期逻辑一致）：

| Metric 类别 | Rate_T1 | Score_T1 | Score_Cap | Rate_T2 | Score_T2 | Rate_T3 | Score_T3 | Floor |
|---|---|---|---|---|---|---|---|---|
| GSV/营收类通用（OPS/SUP/ADS/LIVE/HOST-001、PROD-DIR/EDIT/CAM-001） | 1.0 | 0（比例） | 150 | 0.8 | 90 | 0.6 | 60 | 0 |
| ROI-110（IE-OPS-002） | 0.9 | 0（比例） | 110 | 0.85 | 85 | 0.8 | 80 | 0 |
| ROI-150（IE-SUP-002/ADS-002） | 0.9 | 0（比例） | 150 | 0.8 | 60 | 0 | 0 | 0 |
| PROD-DIR-002（团队产出数量，基准140） | 1.0 | 0（比例） | 120 | 120/140≈0.8571 | 80 | 0 | 0 | 0 |
| PROD-EDIT-002（个人成片数量，基准150） | 1.0 | 0（比例） | 120 | 0.8 | 80 | 0 | 0 | 0 |
| PROD-CAM-002（个人素材数量，基准100） | 1.0 | 100（固定） | 100 | 0 | 0 | 0 | 0 | 0 |
| PROD-DIR/EDIT-003（消耗金额） | 1.0 | 0（比例） | 150 | 0.8 | 90 | 0 | 0 | 0 |

次数阈值型（LIVE-002/003）：Rate_T1=0, Score_T1=100, Rate_T2=3, Score_T2=80/60, Floor=0
扣分制（PROD-CAM-003/004/005、PROD-EDIT-004/005）：Deduct_Per=5, Floor=0

### 3.3 Final_Score（最终单项得分，双部分 D-009.3）

```text
IF(ISBLANK([Auto_Score]) && ISBLANK([Manual_Score]), "",
   IFBLANK([Auto_Score], 0) + IFBLANK([Manual_Score], 0))
```

- 自动得分 + 负责人得分合计（D-009.3「结果模型 = 自动计算部分 + 负责人填写部分」）
- Auto_Score 留空（定性/奖惩）时 Final_Score = Manual_Score；Manual_Score 留空时 = Auto_Score
- 两者都空（待录入）→ 空
- 已验证：定性类录入 Manual_Score=70 → Final_Score=70，Weighted_Score=0.1×70=7，Monthly_Total 同步更新 ✓

### 3.4 Monthly_Total（岗位月度总分）

```text
SUM([Performance_Result].FILTER(CurrentValue.[Employee_ID] = [Employee_ID] && CurrentValue.[Period] = [Period]).[Weighted_Score].LISTCOMBINE())
```

- 同一员工+期间的所有结果行 Weight×Final_Score 之和（加权汇总）
- 权重取自重 Metric（Weight 公式字段 lookup），Weighted_Score 为中间量
- 验证：SUP 员工 0.3×150 + 0.3×90 = 72 ✓；LIVE 员工 0.1×60 + 0.2×100 + 0.2×0 = 26 ✓

### 3.5 Commission_Tier_Level（提成梯度匹配）

```text
FIRST([Commission_Tier].FILTER(
  CurrentValue.[Position_ID] = FIRST([Metric_ID].[Position_ID]) &&
  CurrentValue.[Score_Lower] <= [Monthly_Total] &&
  CurrentValue.[Status] = "Active"
).SORTBY([Commission_Tier].[Tier_Level], FALSE).[Tier_Level])
```

- 按员工岗位（Metric→Position_ID）过滤 Commission_Tier，取 Score_Lower ≤ 总分 的最高档
- **D-009.5 超上限兜底**：总分超过所有有上限档位时，FILTER 条件 Score_Lower ≤ 总分 仍命中最高档（如 OPS 总分 200 → Score_Lower≤200 命中 108 档）——按最高一档处理 ✓
- **与 Upper_Is_Open 的区别**（模型 §5.5 注明）：Upper_Is_Open=true 表示 V04 原文即不设上限的梯度（如 OPS 第7档 upper=None, open=true）；D-009.5 是「有上限梯度被超出时按最高档取值」，两者由同一公式天然覆盖
- 验证：SUP 员工 MT=72 → OPS/SUP 梯度 lower≤72 最高档 = tier3（70≤72<90）✓
