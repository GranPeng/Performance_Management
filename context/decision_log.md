### D-010【已定】Target 与 Metric 一对多共用：贡献区分靠绩效权重，预算不拆分
- 日期：2026-08-14
- 决策：
  1. 一个渠道的预算目标（Target）可被多个岗位指标（Metric）共用，**Target 不拆分、不挂单个 Metric_ID**
  2. 同一业务在不同岗位的应占贡献，由**个人绩效框架中的组织绩效权重**区分（如运营岗组织绩效 70%/个人 30%；各岗位权重不同），该权重落在 `Performance_Result.Weight`（取自 Metric），**不是**按权重拆分预算
  3. Target 与 Metric 的关联通过 `V60_Source_Row`（Target）↔ `Budget_Field_Ref`（Metric）间接多对多匹配，无需新增关联表
  4. 按权重分摊预算留待未来扩展，当前阶段不实现
- 理由：Product Owner 确认。渠道营收由投放/内容/运营多岗位共同承担，是业务常态而非异常；权重属考核口径，与预算分摊是两回事。
- 模型影响：零变更（现有字段承载）。

### D-009【已定】5 项口径确认清单拍板（修复建议 P2-2 全部关闭）
- 日期：2026-08-14
- 决策：
  1. **岗位↔渠道/项目映射**：以飞书「在职人员对照项目」表为准，该表**在线人工维护**，系统直接消费
  2. **90 天归因数据来源**：由视频管理系统自动下载数据，绩效核算直接套数出结果（走 D-007 路径1：建导入表）
  3. **客服奖惩金额**：不进入自动计算规则，由客服主管**手动录入**。确认结果模型结构 = 自动计算部分 + 负责人填写部分，合计出最终结果（参照现有「绩效得分结果（负责人打分）」表结构）
  4. **高级主管免责提成**：无法完全数字化，由 HR 人工评判（走负责人填写/人工部分，不进公式）
  5. **超梯度上限得分处理**：按最高一档处理
- 理由：Product Owner 口头确认。修复建议 §5 P2-2 的 7 项待确认清单至此全部关闭（前 2 项见 D-005）。
- 模型影响：Performance_Result 必须采用「自动得分 + 人工填写 → 合计最终结果」的双部分结构；Project_Member 数据源为在线维护的「在职人员对照项目」；梯度表边界语义为「超上限按最高档」。
