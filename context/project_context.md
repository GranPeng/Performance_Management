# 项目上下文（Project Context）

> 本文件回答：**这个项目为什么这样设计？** 新加入的 Agent 必须先读懂本文件，再碰任何代码或文档。

## 1. 项目是什么

一套企业绩效核算系统。每月末，系统需要完成：

1. 收集各岗位的**目标达成数据**（业务员通过飞书与 bot 对话上报）
2. AI Agent 将对话中的达成数据**誊写**进飞书多维表格
3. 多维表格内按既定框架和公式**自动完成绩效核算**
4. 输出最终绩效结果（得分 → 提成/奖金）

## 2. 系统最终形态（用户已确认，2026-08-14）

- **数据入口**：业务员在飞书与 bot 对话，传输每月应收集录入的达成数据
- **数据誊写**：Agent 负责把达成数据写入飞书多维表格
- **核算引擎**：飞书多维表格通过已搭建的框架和公式自动完成核算
- **Kanban 的角色**：只用于**本系统的开发过程管理**，不参与系统上线后的日常运营

## 3. 为什么这样设计（设计哲学）

本系统要长期运行，每月都要算钱——**算错钱比算得慢严重得多**。因此：

- 宁可自动化慢一步，也要数据结构和业务规则先正确
- 宁可多一道人工复核，也不能让 Agent 静默改数
- Excel 是人看的输入层，飞书是计算和展示层，Canonical Data Model 是唯一事实来源
- 任何计算结果必须能回答「为什么得到这个分数」——可解释、可追溯、可复核

详见 `.hermes/PROJECT_RULES.md` §1 Core System Philosophy。

## 4. 系统架构（固定，不可更改）

```
Excel Input → Data Validation → Agent ETL Pipeline
→ Canonical Data Model → Feishu Base
→ Calculation Engine → Performance Result
```
