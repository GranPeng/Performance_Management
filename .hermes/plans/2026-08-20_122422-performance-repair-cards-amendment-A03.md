# 全量修复发卡计划 · 修订附录 A03（扇出与权限决策）

> 本附录优先于主计划、A01、A02 中关于 Actual 多匹配和重算登录/授权的表述。

## C1：Actual 多匹配（扇出）已确认口径

### 正常自动关联

服务端仍按以下键匹配：

`期间 + 指标 + 员工/组织/项目/渠道`

只有候选 `performance_result` 恰为 1 条时，自动关联并参与计算。

### 共享扇出

仅当**指标已被显式配置为“共享总量指标”**时，允许一条 Actual 同时关联多条 Result：

- 同一 Actual 作为多个员工/项目结果的共同实际值；
- 各候选 Result 均读取同一实际值计算自身的达成率/得分；
- 此规则仅适用于共同 KPI，不能用于个人贡献拆分；
- Dashboard、结果书的金额/总量聚合仍必须按既定“员工 + 期间”或实际业务粒度去重，禁止因 link 扇出而重复累计。

### 非共享多匹配

若候选多条 Result，但该 Metric 未显式配置“共享总量指标”：

- API 返回业务可读的多匹配错误；
- 不创建/不更新 Actual→Result 关联；
- 返回候选结果的稳定 ID、员工/期间/指标摘要，供后续人工分配或配置分摊规则；
- 禁止默认平均分摊，禁止静默选第一条。

### C1/C2 追加验收

1. 唯一匹配：自动关联成功，preview/run 读取新 Actual；
2. 已配置共享指标：同一 Actual 合法关联多条 Result，所有相关 Result 使用同一实际值；
3. 未配置共享指标的多匹配：API 拒绝，数据库零关联变更；
4. 不允许任何按候选人数自动平均分摊逻辑；
5. “共享总量指标”的配置来源、字段、变更权限、历史回放规则必须在 C1 设计卡中明确，并由 PO 验收。

## D1/D2：权限配置延后已确认

- `calc/run` 的基础登录保护、角色授权、绩效管理员矩阵、操作人审计均移至最后配置；
- 在权限配置完成前，P3c/G1 的重算/导出相关前端入口继续保持阻塞，不得发布；
- 不得以“前端未提供按钮”宣称服务端端点安全；当前服务端端点的未显式保护风险由 PO 知悉并接受为延后项；
- 任何新卡不得扩展、宣传或新建对该端点的公开调用方式；
- 完整权限配置仍必须在产品功能恢复前完成并经线上验收。

## 依赖调整

```text
C1（定义共享总量指标配置） → C2（唯一匹配 + 共享扇出 + 非共享拒绝） → C3
D1/D2 保持在 Q1 后、G1 前；G1 不得绕过 D2 上线重算/导出入口
```
